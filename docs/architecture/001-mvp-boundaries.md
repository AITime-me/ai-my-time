# ADR-001: границы MVP Telegram-контура A.I. My Time

**Статус:** принято для локальной разработки  
**Дата:** 2026-08-26

## Контекст

К конференции нужен не отдельный «бот ради бота», а один сквозной путь:

`источник → Lead Bot → сегментация → Diagnostic AI → персональный результат → AI Assistant / Zoom / человек`.

У проекта уже есть TanStack/Lovable сайт с публичными страницами и UI Admin. В других репозиториях есть проверенные паттерны backend, PostgreSQL, worker, Admin и операций. Эти проекты нельзя смешивать по данным или бизнес-логике.

## Решение

### Рантаймы

| Контур | Назначение | Статус MVP |
|---|---|---|
| `site` | Существующая публичная витрина A.I. My Time и CTA | сохраняем и постепенно отвязываем от Supabase |
| `admin` | Внутренняя операционная панель | отдельное приложение; UI и паттерны берём из `online-zapis-tv`, сущности — только A.I. My Time |
| `core-api` | FastAPI: доменная логика, webhook, Admin API, аутентификация сервисов | новый сервис на паттернах `bot-TV` |
| `worker` | Очереди, retries, диагностики, рассылки, запланированные задачи | новый сервис на том же коде, отдельный процесс |
| `postgres` | Единственная production-база A.I. My Time | отдельная БД, пользователь и volume |
| `reverse-proxy` | HTTPS и маршрутизация публичных/внутренних приложений | отдельный слой после согласования production deploy |

### Модель пользователя

- Один внутренний UUID на человека.
- Telegram `user_id` — стабильная identity; username не является ключом.
- Lead Bot и AI Assistant используют общую identity и общую историю, но разные типы диалога.
- Источник первого входа и все последующие touchpoint-события не перезаписывают друг друга.

### Диагностика

- Diagnostic AI не является свободным чатом.
- Входом служат только структурированные ответы и утверждённая методология.
- Результат имеет фиксированный формат, версию методологии и сохраняется вместе со входным snapshot.
- Цена, срок и конкретная интеграция не обещаются без проверки человеком.

### Границы MVP

В MVP до конференции входят: Lead Bot, source-метки, conference_2026, сегментация, Diagnostic AI, карточка человека и результата в Admin, запрос Zoom/реализации, базовые backup/health/error log.

Не входят: amoCRM, VK, сложная CRM-воронка, задачи, договоры, телефония, BI и полноценный движок автоматических рассылок.

## Переиспользование

- Из `bot-TV`: Alembic, PostgreSQL-сессии, durable ingress, идемпотентность, worker/heartbeat/retry, event history, health-паттерны.
- Из `online-zapis-tv`: UI-паттерны Admin, auth/layout/table/filter/card, операции backup/restore/monitoring.
- Из текущего `ai-my-time`: публичные страницы, визуальная система, CTA, SEO, контентные сущности как UX-референс.

Ни таблицы, ни данные, ни студийная бизнес-логика из исходных проектов не копируются в A.I. My Time.

## Порядок реализации

1. Добавить backend-каркас и изолированную доменную схему без production deploy.
2. Реализовать Telegram ingress и один сценарий `conference_2026`.
3. Добавить Diagnostic AI и отображение результата в Admin.
4. Провести сквозные тесты: завершение, прерывание, возврат, handoff, повтор webhook.
5. Отдельно согласовать production Docker/HTTPS/backup rollout.

## Проверка и rollback

- Каждая миграция проходит на пустой локальной PostgreSQL до production.
- Каждый шаг имеет Git commit, тест и краткий change record.
- До первого production webhook обязательны backup, пробное восстановление, health endpoint и журнал ошибок.
- Production не меняется из этой ADR.
